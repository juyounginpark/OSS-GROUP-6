## 📝 작성 양식

각자의 폴더 안에 있는 개인 Markdown 파일에 아래 순서로 작성합니다.

1. 나라 소개 · Intro
2. 유명 여행지
3. 유명 음식
4. 자유 주제 단락
5. 마무리 및 본인이 추천하는 코스

사진은 각자 폴더의 `images/`에 넣고 개인 Markdown에서 연결합니다.
현재는 임시 국기 이미지와 빈 작성 양식만 준비되어 있습니다.

## 🌿 브랜치 작업 방법

**최종 제출 전까지 각자 브랜치에서 작업하고, 모든 작업을 마친 뒤 각자 PR을 만들어 `main`에 합칩니다.** 개인 여행 페이지는 `main`에서 직접 수정하지 않습니다.

| 작성자 | 나라 | 작업 브랜치 | 작업 폴더 |
| :--- | :--- | :--- | :--- |
| 이원기 | 영국 | `uk` | `이원기_영국/` |
| 박주영 | 그리스 | `greece` | `박주영_그리스/` |
| 정현호 | 일본 | `japan` | `정현호_일본/` |
| 이윤호 | 멕시코 | `mexico` | `이윤호_멕시코/` |
| 이상민 | 이탈리아 | `italy` | `이상민_이탈리아/` |

### 1. 자신의 브랜치로 이동

아래는 이원기(영국) 예시입니다. 다른 팀원은 브랜치와 폴더를 자신의 것으로 바꿔 실행합니다.

```bash
git fetch origin
git switch uk
git pull --ff-only origin uk
```

로컬에 브랜치가 없다면 `git switch uk` 대신 `git switch --track origin/uk`를 실행합니다. 파일을 수정하기 전에 `git branch --show-current`로 자신의 브랜치인지 확인합니다.

### 2. 작성 → 커밋 → 푸시

자신의 폴더에서 내용을 작성하고, 의미 있는 변경 단위로 커밋합니다.

```bash
git add "이원기_영국/"
git commit -m "[ADD] 영국 나라 소개 작성"
git push origin uk
```

**10월 14·15·16·17·18일에 각자 하루 3개씩, 총 15개 커밋을 작성합니다.** 날짜는 한국 시간 기준이며, 커밋 후 자신의 이슈에서 체크합니다.

### 3. 마지막에 PR로 마무리

1. 최종 내용을 자신의 브랜치에 커밋하고 푸시합니다.
2. GitHub의 **Pull requests → New pull request**에서 `base: main`, `compare: 자신의 브랜치`를 선택합니다.
3. 제목은 `[ADD] 이원기 영국 여행 페이지 완성`처럼 작성하고, 본문에는 작성 내용과 자신의 이슈 번호를 적습니다. 예: `Closes #1`.
4. 변경 파일과 이미지·링크가 정상인지 팀원이 확인한 뒤 `main`에 병합합니다. 기존 커밋을 유지하려면 **Create a merge commit** 방식을 사용합니다.
5. 모든 팀원의 PR이 병합되면 최종 제출을 마무리합니다. `Closes #번호`로 연결한 이슈는 `main`에 병합될 때 자동으로 닫힙니다.

## 💬 커밋 컨벤션

커밋 메시지는 **`[TYPE] 변경 내용`** 형식으로 작성합니다. 타입은 대문자로 쓰고, 무엇을 바꿨는지 짧고 구체적으로 적습니다.

| 타입 | 사용 상황 | 예시 |
| :--- | :--- | :--- |
| `[ADD]` | 새로운 내용·이미지·파일 추가 | `[ADD] 그리스 유명 여행지 소개 추가` |
| `[UPDATE]` | 기존 내용 보완·변경 | `[UPDATE] 일본 추천 코스 설명 보완` |
| `[FIX]` | 오타·깨진 링크·이미지 경로 수정 | `[FIX] 멕시코 음식 이미지 경로 수정` |
| `[DOCS]` | README 등 프로젝트 안내 문서 작성·수정 | `[DOCS] 브랜치 작업 및 커밋 규칙 안내 추가` |
| `[STYLE]` | 내용 변경 없이 Markdown 서식 정리 | `[STYLE] 이탈리아 여행 페이지 제목 간격 정리` |
| `[CHORE]` | 프로젝트 설정·기타 관리 작업 | `[CHORE] .gitignore 설정 추가` |

하루 3개 커밋은 실제 작업을 나눠 작성합니다. 예를 들어 나라 소개, 여행지 소개, 음식 소개를 각각 완료한 뒤 아래처럼 커밋할 수 있습니다.

```text
[ADD] 영국 나라 소개 작성
[ADD] 영국 유명 여행지 소개 추가
[ADD] 영국 유명 음식 소개 추가
```

## ✅ 이슈 체크 방법

| 작성자 | 나라 | 커밋 날짜 체크 이슈 |
| :--- | :--- | :--- |
| 이원기 | 영국 | [#1](https://github.com/juyounginpark/OSS-GROUP-6/issues/1) |
| 박주영 | 그리스 | [#2](https://github.com/juyounginpark/OSS-GROUP-6/issues/2) |
| 정현호 | 일본 | [#3](https://github.com/juyounginpark/OSS-GROUP-6/issues/3) |
| 이윤호 | 멕시코 | [#4](https://github.com/juyounginpark/OSS-GROUP-6/issues/4) |
| 이상민 | 이탈리아 | [#5](https://github.com/juyounginpark/OSS-GROUP-6/issues/5) |

1. GitHub **Issues**에서 자신의 이름·나라가 적힌 이슈를 엽니다.
2. 커밋하고 푸시한 뒤, 해당 날짜의 `커밋 1·2·3` 체크박스를 하나씩 직접 클릭합니다. 자동으로 체크되지는 않습니다.
3. 필요하면 이슈 본문을 수정해 해당 항목 뒤에 커밋 링크를 붙입니다. 클릭할 수 없다면 본문 수정에서 `- [ ]`를 `- [x]`로 바꿔 저장합니다.
4. 모든 체크를 완료한 뒤 최종 PR 본문에 `Closes #자신의 이슈 번호`를 적어 연결합니다.

**이슈를 만들거나 수정하고 체크박스를 바꿔도 Git 커밋은 추가되지 않습니다.** 실제 파일 변경을 `git commit`해야 커밋이 만들어집니다.
